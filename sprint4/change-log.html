Sprint 4 · Change Log

What Sprint 4 changed

Quality targets and issue handling entered the plan. Lot onboarding is called out as work the 538-hour estimate does not yet include.

  • Sprint 4
  • Quality Metrics
  • Change Log
  • Retrospective

Recorded changes

  1. CH-01 Camera coverage target. Monitored lots need 90% camera coverage so enough stalls stay visible. That coverage number is now a requirement.
  2. CH-02 Parking availability accuracy. Counts shown to drivers should match a manual count at least 90% of the time. The team has to check that regularly.
  3. CH-03 Data freshness requirement. Updates should be under 2 minutes for 95% of the day, so drivers are not using an old count. Each lot needs monitoring.
  4. CH-04 Stale-data warnings. If accuracy or freshness misses its target, the interface should say the information may be unreliable. That is a possible UI requirement.
  5. CH-05 Issue severity classification. Three severity levels set how fast a problem is fixed and who is told.
  6. CH-06 Parking lot onboarding estimate. Bringing a new lot online was not in the original 538-hour estimate. Schedule and budget may need an update if that work is added.
